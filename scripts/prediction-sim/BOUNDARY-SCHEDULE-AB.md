# Offline VAD boundary-schedule A/B

This is the Phase 1 runbook for the gap-retention policy decision in
`.opencode/plans/2026-10-25-vad-gap-retention.md`. It generates VAD schedules
in Ritoras and decodes each scheduled window through Whisper's production
`ParakeetV2Engine.transcribe_array_streaming` API. It does not change either
production recorder or server path.

The decode runner lives in the other repository at
`/home/michael/whisper/benchmark/ab-boundary-schedules.py`.

## Generate schedules

Run from any directory. Both policies use the same shipping adaptive VAD
configuration unless identical `--set k=v` overrides are added to both
commands. The simulator accepts one or more positional WAVs and writes one
JSON schedule per WAV. It rejects non-mono or non-16-kHz input.

```sh
RITORAS=/home/michael/.local/share/opencode/worktree/19779c7e2e6563cec9a9532dafe5e880516a0733/glowing-knight
CORPUS=/tmp/opencode/gap-retention-corpus
RESULTS=/tmp/opencode/gap-retention-results
mkdir -p "$RESULTS/schedules/current" "$RESULTS/schedules/gap-retention" \
  "$RESULTS/decode"
WAVS=("$CORPUS"/*.wav)
node "$RITORAS/scripts/prediction-sim/bin/sim-boundary-schedule.mjs" \
  --policy current --output-dir "$RESULTS/schedules/current" "${WAVS[@]}"
node "$RITORAS/scripts/prediction-sim/bin/sim-boundary-schedule.mjs" \
  --policy gap-retention --output-dir "$RESULTS/schedules/gap-retention" "${WAVS[@]}"
```

The current schedule is generated by `replaySession()` from
`scripts/prediction-sim/bin/replay-vad.mjs`, which drives the existing
`makeRecorderHarness()` in `lib/recorder-sim.mjs`; it therefore retains today's
head/pre-roll, post-roll trim, endpoint, gate, and split behavior rather than a
second hand-written approximation. Its uncovered intervals are reported as
legacy-unretained/trimmed slabs.

Both arms share the replay WAV dB path: `dcCorrectedRMS()` and `dbFromSamples()`
at `replay-vad.mjs:415-427` compute DC-corrected RMS and pass it to
`dbFromRms()`; `framesFromWav()` at `replay-vad.mjs:495-519` slices the WAV into
10 ms frames and assigns that dB value. The simulator calls this same
`replaySession(..., { fromWav })` path. `analysisHpfEnabled` is false by default,
so no additional filter changes the telemetry-matched dB convention.

## Decode the schedules offline

The Whisper runner validates the WAV hash/sample count in each schedule,
preflights the materialized ASR directory without downloading, loads one engine
for all schedules, and invokes the production streaming API once per chunk.
Cleanup-model loading alone is disabled in memory, matching the existing
`replay-zero-token.py` offline diagnostic. Hugging Face offline environment
variables are forced on by the runner.

Within each policy arm, the runner carries the last 300 characters of accepted
prior chunk text as `previous_context`, following the ordered streaming replay
pattern in `variant-replay.py`. The first-word signal is measured from the raw
engine result; server-side post-decode casing is not applied by the runner.

The profile's default materialized Parakeet v2 path is shown below. If the
materialized directory is elsewhere, pass its actual path as `--model-dir`; the
runner refuses to start if that directory is not complete.

```sh
WHISPER=/home/michael/whisper
CORPUS=/tmp/opencode/gap-retention-corpus
RESULTS=/tmp/opencode/gap-retention-results
MODEL_DIR=/home/michael/whisper/server-v2/models/onnx-asr-nemo-parakeet-tdt-0.6b-v2--unquantized

for wav in "$CORPUS"/*.wav; do
  id=$(basename "$wav" .wav)
  "$WHISPER/server-v2/.venv-test/bin/python" \
    "$WHISPER/benchmark/ab-boundary-schedules.py" \
    --wav "$wav" \
    --schedule "$RESULTS/schedules/current/$id.current.json" \
    --schedule "$RESULTS/schedules/gap-retention/$id.gap-retention.json" \
    --config "$WHISPER/server-v2/parakeet-v2.json" \
    --model-dir "$MODEL_DIR" \
    --output "$RESULTS/decode/$id.ab.jsonl"
done
```

Expected artifacts:

```text
/tmp/opencode/gap-retention-results/
├── schedules/
│   ├── current/<id>.current.json
│   ├── current/current.corpus-summary.json
│   ├── gap-retention/<id>.gap-retention.json
│   └── gap-retention/gap-retention.corpus-summary.json
└── decode/<id>.ab.jsonl
```

Each decode JSONL contains a run header, one `chunk_result` or `chunk_error`
per scheduled window, one `policy_summary` per policy, and a final
`comparison_summary`. The policy summaries retain full concatenated and
per-chunk transcripts, gate outcomes, first alphabetic word/case, server
lowercase-continuation signal, zero-token and zero-voice counts, decode time,
and the schedule's emitted/shed coverage totals. The gap-retention per-WAV
schedule and corpus summaries also report stop-flush chunk/offered-audio counts
and non-split below-minimum endpoint-finalize event counts with duration/voice
evidence; held events do not represent discarded audio. Event duration/voice
totals are diagnostic sums and may count the same retained buffer at multiple
finalizes. The comparison record reports endpoint-finalize gate regressions and
seam signal flips by boundary ordinal.

## Phase 1 PASS criteria (plan acceptance a-d)

1. **Coverage (a), each gap-retention schedule:**
   - `coverage.buckets_are_disjoint == true`,
     `coverage.coverage_matches_total == true`, and `coverage.uncovered_ms == 0`.
     Check `emitted_samples + shed_samples + tail_floor_drop_samples ==
     total_samples` as the exact sample-level equality; the millisecond totals
     should reconcile as well.
   - `uncovered_slabs` is empty. Every `shed_slabs` row must be a whole pending
     interval longer than 6.0 seconds (`end_sample - start_sample > 96000`)
     with `voice_ms < 100`.
   - Every `tail_floor_drops` row must have `reason == "tail-floor"` and
     `duration_ms < 250`; record its `voice_ms`. The bucket is only for the
     short stop tail and is not a voice gate.
   - The policy's `*.corpus-summary.json` must report the same emitted/shed/
     tail-floor/uncovered totals as the sum of its per-WAV `coverage` records,
     including sample counts, with `coverage_matches_total == true` and no
     uncovered samples.
   - Each `endpoint-finalize-held` event must have `split == false`,
     `emitted == false`, and `duration_ms`/`voice_ms`. These events are
     informational: their audio remains buffered and is later included in an
     emission or stop-flush, not counted as a discarded bucket. Min-speech and
     min-chunk gates control endpoint/split emissions only; they never discard
     retained samples.
   - Stop-flush offers all non-shed pending audio regardless of endpoint state,
     chunk size, or voice evidence. Short and pure-silence tails may be emitted;
     downstream server defenses handle them.
   - For `232629`, the first two gap-retention windows must be adjacent at the
     first endpoint boundary (`chunks[1].start_sample == chunks[0].end_sample`);
     the following chunk's `onset_ms` must be later than its `start_ms`. Verify
     the known >=2.3-second inter-utterance gap is covered by those adjacent
     windows and is absent from `shed_slabs`/`uncovered_slabs`. The chunk end
     remains its endpoint-finalize sample; it is not post-roll trimmed.
2. **Decode compatibility (b), for each WAV:**
   - `comparison_summary.gate_comparison.no_new_gate_failures == true`, with
     empty `new_gate_failures` and
     `unpaired_candidate_gated_chunk_indices`.
   - `comparison_summary.error_count == 0`; each policy's
     `completed_chunk_count == chunk_count`; and
     `missing_gap_retention_endpoint_finalize_indices` is empty. Any additional
     candidate endpoint finalize index must be reviewed against its audio/text.
   - `comparison_summary.seam_comparison.no_seam_flips == true`, with
     `flip_count == 0` and `unmatched_count == 0`. A flip is a change in the
     server's actual classification signal,
     `first_alphabetic_word[0].islower()` for the following chunk; schedule JSON
     itself cannot know that word. In this checkout the classifier is
     `server.py:1619-1621`; cited lines `server.py:1623-1625` enter the adjacent
     forced-case helper.
   - Read the current and gap-retention `transcript` and `chunk_texts` together
     and record any changed, missing, or added words against the continuous
     recording/reference. The runner makes those values and gate rows explicit;
     do not infer transcript quality from chunk count or text equality alone.
3. **Mostly-silence/zero-token behavior (c):**
   - Check `zero_token_count`, `zero_token_nonempty_text_count`,
     `zero_voice_chunk_count`, and `zero_voice_nonempty_text_count` in each
     policy summary, plus each row's `voice_ms`, `above_silence_ms`,
     `voice_fraction`, `duration_ms`, token count, text, `gated`, and reason.
   - Inspect every zero-voice/mostly-silence result's text, tokens, `gated`, and
     reason. Record any non-empty noise transcription or zero-token result and
     whether the server gate/rescue defenses suppress it. A rare short noise
     word is an accepted tradeoff only if it matches the user's stated
     tolerance; summarize the observed rate even when counts are zero.
4. **Freeze evidence (d):**
   - Record the config/WAV hashes, corpus IDs, gate/seam summary, all zero-token
     counts, and transcript review outcome in the template below.
   - Freeze the 6.0-second cap, the voice-band mapping (strong/continuing counts
     toward the 100 ms shed guard; retained audio is offered at stop), and the
     stop-flush offer rule only if (a)-(c) pass. Otherwise record the exact
     adjustment and rerun both schedule and decode arms over the same WAVs
     before Phase 2.
